## 1. Overview

This document specifies the integration contract between **AgentShield** (Python, local SIEM-lite for AI agent security monitoring) and **OpenClaw** (TypeScript, cloud-hosted AI agent runtime). The integration enables AgentShield to evaluate OpenClaw tool calls in real time, returning allow/block/log decisions before tools execute.

### Design Principles

1. **Fail-open by default** -- if AgentShield is unavailable, OpenClaw proceeds normally.
2. **Minimal latency** -- synchronous evaluation path must complete within a configurable timeout (default 50ms).
3. **Zero overhead when disabled** -- the OpenClaw plugin adds no cost when AgentShield integration is off.
4. **Backward compatible** -- existing AgentShield log-based monitoring and existing OpenClaw tool policies continue to work unchanged.
5. **Auditable** -- all decisions (allow, block, timeout) are logged on both sides.

### Integration Architecture

```
OpenClaw (TypeScript)                     AgentShield (Python)
+----------------------------+            +----------------------------+
| Pi Agent Loop              |            | RealtimeReceiver           |
|   |                        |            |   (aiohttp / uvicorn)      |
|   v                        |            |                            |
| before_tool_call hook      |  HTTP POST | POST /api/v1/evaluate      |
|   -> AgentShield plugin ---|----------->|   -> Parse Event           |
|   <- await response     <--|<-----------|   -> DetectionEngine       |
|   |                        |  JSON resp |   -> Action decision       |
|   v                        |            |   -> Return response       |
| if block: throw Error      |            |                            |
| if allow: continue         |            | Background:                |
| if modify: update params   |            |   -> EventStore.insert()   |
|   |                        |            |   -> AlertStore.insert()   |
|   v                        |            |   -> TriageAgent (async)   |
| Tool execution             |            |   -> Notify (async)        |
|   |                        |            +----------------------------+
|   v                        |
| after_tool_call hook       |  HTTP POST (fire-and-forget)
|   -> audit report ---------|-----------> POST /api/v1/audit
+----------------------------+
```

## 2. Event Schema

### 2.1 Evaluation Request (OpenClaw -> AgentShield)

Sent as the body of `POST /api/v1/evaluate`.

```jsonc
{
  // Required fields
  "event_id": "string",           // UUID v4, generated by OpenClaw plugin
  "timestamp": "string",          // ISO 8601 with timezone, e.g. "2026-02-07T12:00:00.000Z"
  "event_type": "string",         // Normalised event type (see Section 2.4)
  "tool_name": "string",          // OpenClaw tool name: "exec", "write", "read", "edit", "browser", etc.
  "source": "openclaw",           // Fixed string identifying the source system

  // Tool call details
  "command": "string | null",     // For exec: the shell command. For file ops: "Write: /path" etc.
  "params": {},                   // Full tool parameters as JSON object (tool-specific)

  // Context fields
  "agent_id": "string | null",    // OpenClaw agent identifier
  "session_id": "string | null",  // OpenClaw session key
  "working_dir": "string | null", // Current working directory (if known)

  // Extensible metadata
  "data": {}                      // Arbitrary key-value pairs for future use
}
```

### 2.2 Evaluation Response (AgentShield -> OpenClaw)

Returned as the response body of `POST /api/v1/evaluate`.

```jsonc
{
  // Required fields
  "action": "allow" | "block" | "log",  // Decision (see Section 2.5)
  "event_id": "string",                  // Echo of request event_id

  // Present only when action != "allow"
  "alerts": [                             // List of triggered detection rules
    {
      "rule_id": "string",               // Sigma rule ID
      "rule_name": "string",             // Human-readable rule name
      "level": "low" | "medium" | "high" | "critical",
      "description": "string | null"     // Rule description
    }
  ],

  // Present only when action == "block"
  "reason": "string",                    // Human-readable block reason for the agent

  // Present only when action == "modify" (future extension)
  "modified_params": {}                  // Modified tool parameters (reserved, not v1)
}
```

### 2.3 Audit Report (OpenClaw -> AgentShield, fire-and-forget)

Sent as the body of `POST /api/v1/audit` after tool execution completes.

```jsonc
{
  "event_id": "string",           // UUID v4, new ID for this audit event
  "correlation_id": "string",     // event_id from the original evaluation request
  "timestamp": "string",          // ISO 8601
  "event_type": "tool_result",    // Fixed
  "tool_name": "string",
  "source": "openclaw",

  // Execution outcome
  "result_summary": "string | null",  // Truncated result (max 1000 chars)
  "is_error": false,                   // Whether tool execution raised an error
  "error_message": "string | null",    // Error message if is_error=true
  "duration_ms": 0,                    // Execution time in milliseconds

  // Context (same as evaluation request)
  "agent_id": "string | null",
  "session_id": "string | null",
  "working_dir": "string | null",
  "data": {}
}
```

### 2.4 Event Type Normalisation

OpenClaw tool names are mapped to AgentShield event types for Sigma rule matching:

| OpenClaw Tool | `event_type` | `command` Field |
|---|---|---|
| `exec` | `"tool_call"` | `params.command` (shell command string) |
| `write` | `"file_write"` | `"Write: {params.filePath}"` |
| `read` | `"file_read"` | `"Read: {params.filePath}"` |
| `edit` | `"file_edit"` | `"Edit: {params.filePath}"` |
| `browser` | `"browser_action"` | `"{params.action}: {params.url or ''}"` |
| `message` | `"message_send"` | `"Message to {params.channel}"` |
| `sessions_spawn` | `"session_spawn"` | `"Spawn: {params.agentId}"` |
| Other | `"tool_call"` | `tool_name` |

This mapping is performed by the OpenClaw plugin before sending the request. AgentShield's existing Sigma rules (which match on `event_type` and `command`) work without modification.

### 2.5 Action Decision Matrix

AgentShield determines the `action` based on the maximum alert severity:

| Alerts Generated | Max Level | Default Action | Configurable? |
|---|---|---|---|
| None | -- | `allow` | No |
| Any | `low` | `log` | Yes: can escalate to `block` |
| Any | `medium` | `log` | Yes: can escalate to `block` |
| Any | `high` | `block` | Yes: can downgrade to `log` |
| Any | `critical` | `block` | No (always block critical) |

The threshold is configurable via AgentShield's `config.yaml`:

```yaml
realtime:
  block_threshold: "high"   # "critical" | "high" | "medium" | "low"
```

When `block_threshold: "critical"`, only critical alerts cause blocks; high/medium/low produce `log`. When `block_threshold: "medium"`, medium and above cause blocks.

## 3. Transport Mechanism

### 3.1 Protocol: HTTP/1.1 over localhost

**Choice: HTTP POST over TCP on localhost** (127.0.0.1).

Rationale:
- Both services run on the same machine in the target deployment.
- HTTP is universally debuggable (curl, browser devtools, Wireshark).
- Native timeout support via TCP and application-level timeouts.
- No binary protocol complexity (vs. gRPC).
- No persistent connection management (vs. WebSocket).
- Localhost TCP round-trip is ~0.2ms, well within budget.

**Future upgrade path**: Unix domain socket for sub-millisecond latency if HTTP overhead proves measurable. The contract remains identical (HTTP over UDS), only the transport layer changes.

### 3.2 Endpoint Definitions

| Endpoint | Method | Purpose | Blocking? |
|---|---|---|---|
| `/api/v1/evaluate` | POST | Synchronous tool call evaluation | Yes (caller awaits) |
| `/api/v1/audit` | POST | Post-execution audit record | No (fire-and-forget) |
| `/api/v1/lifecycle` | POST | Session/agent lifecycle events | No (fire-and-forget) |
| `/api/v1/health` | GET | Health check / readiness probe | No |
| `/api/v1/status` | GET | Service status and rule count | No |

### 3.3 Content Type

All requests and responses use `Content-Type: application/json; charset=utf-8`.

### 3.4 Default Binding

```
Host: 127.0.0.1
Port: 8432
```

Configurable on both sides:
- **AgentShield**: `realtime.host` and `realtime.port` in `config.yaml`
- **OpenClaw**: `plugins.agentshield.endpoint` in OpenClaw config

### 3.5 Health Check

```
GET /api/v1/health

Response 200:
{
  "status": "ok",
  "version": "1.0.0",
  "rules_loaded": 5,
  "uptime_seconds": 3600
}
```

The OpenClaw plugin can use this endpoint at startup to verify AgentShield is reachable before enabling interception.

## 4. Latency Budget

### 4.1 End-to-End Target

**Default timeout: 50ms** from OpenClaw sending the HTTP request to receiving the response.

### 4.2 Breakdown

| Step | Owner | Estimated Time |
|---|---|---|
| JSON serialisation (request) | OpenClaw plugin | ~0.5ms |
| HTTP send (localhost TCP) | Network | ~0.2ms |
| HTTP parsing + JSON deserialisation | AgentShield | ~1.0ms |
| Pydantic model validation | AgentShield | ~0.5ms |
| `DetectionEngine.evaluate()` (5-10 rules) | AgentShield | ~0.5ms |
| Action decision logic | AgentShield | ~0.1ms |
| JSON serialisation (response) | AgentShield | ~0.3ms |
| HTTP send (response) | Network | ~0.2ms |
| JSON deserialisation (response) | OpenClaw plugin | ~0.3ms |
| **Total estimated** | | **~3.6ms** |

This leaves ~46ms of headroom within the 50ms budget.

### 4.3 Configuration

Both sides configure the timeout independently:

**OpenClaw side** (controls the HTTP client timeout):
```yaml
plugins:
  agentshield:
    timeout_ms: 50    # HTTP request timeout in milliseconds
```

**AgentShield side** (informational, for monitoring):
```yaml
realtime:
  target_latency_ms: 50   # Used for latency percentile alerting
```

### 4.4 Timeout Behaviour

When the OpenClaw plugin's HTTP request exceeds `timeout_ms`:

1. The `AbortSignal.timeout()` fires, aborting the fetch.
2. The plugin applies the configured `timeout_policy` (see Section 5).
3. A timeout event is logged on the OpenClaw side.
4. AgentShield's in-flight processing continues (the event is still stored for audit).

## 5. Failure Modes

### 5.1 Failure Scenarios

| Scenario | OpenClaw Behaviour | AgentShield Behaviour |
|---|---|---|
| AgentShield not running | Apply `timeout_policy` (default: allow) | N/A |
| HTTP connection refused | Apply `timeout_policy` immediately (no wait) | N/A |
| HTTP timeout (> timeout_ms) | Apply `timeout_policy`, log warning | Continue processing (background) |
| AgentShield returns HTTP 5xx | Apply `timeout_policy`, log error | Log internal error |
| AgentShield returns invalid JSON | Apply `timeout_policy`, log error | N/A (bug) |
| AgentShield returns HTTP 400 | Allow (client error, likely schema mismatch) | Log validation error |
| DetectionEngine error | N/A | Return `{"action": "allow"}` + log error |
| Database write failure | N/A | Synchronous path unaffected (writes async) |

### 5.2 Timeout Policy (OpenClaw Configuration)

```yaml
plugins:
  agentshield:
    timeout_policy: "allow"   # "allow" | "block" | "log"
```

| Policy | Meaning |
|---|---|
| `allow` | **Fail-open** (default). Tool executes normally if AgentShield is unavailable. |
| `block` | **Fail-closed**. Tool is blocked if AgentShield cannot respond. Use for high-security deployments. |
| `log` | Allow execution but log a warning that evaluation was skipped. |

### 5.3 Circuit Breaker (OpenClaw Plugin)

To avoid repeatedly waiting for a dead AgentShield instance, the OpenClaw plugin implements a simple circuit breaker:

| State | Behaviour | Transition |
|---|---|---|
| **Closed** (normal) | Send evaluation request for every tool call | After N consecutive failures -> Open |
| **Open** (tripped) | Skip evaluation, apply `timeout_policy` immediately | After `recovery_interval_ms` -> Half-Open |
| **Half-Open** (probing) | Send evaluation for next tool call | If success -> Closed; if failure -> Open |

Default parameters:
```yaml
plugins:
  agentshield:
    circuit_breaker:
      failure_threshold: 3           # Consecutive failures before opening
      recovery_interval_ms: 30000    # 30 seconds before retrying
```

### 5.4 Graceful Degradation on AgentShield Side

If AgentShield's `DetectionEngine` encounters an error during evaluation:

```python
try:
    alerts = engine.evaluate(event)
except Exception as e:
    logger.error("Detection evaluation failed: %s", e)
    return {"action": "allow", "event_id": event_id, "alerts": []}
```

The synchronous path always returns a valid response. Internal errors never cause HTTP 5xx for the evaluation endpoint.

## 6. Request/Response Protocol

### 6.1 Sequence Diagram

```
OpenClaw Agent Loop                 OpenClaw Plugin              AgentShield Realtime
      |                                  |                            |
      | LLM decides to call tool         |                            |
      |--------------------------------->|                            |
      |  before_tool_call(name, params)  |                            |
      |                                  |                            |
      |                                  | POST /api/v1/evaluate      |
      |                                  |--------------------------->|
      |                                  |                            | parse + validate
      |                                  |                            | evaluate(event)
      |                                  |                            | decide action
      |                                  |<---------------------------|
      |                                  | {action, alerts, reason}   |
      |                                  |                            |
      |<---------------------------------|                            |
      | if block: throw Error(reason)    |                            |
      | if allow/log: continue           |                            |
      |                                  |                            |
      | Execute tool                     |                            |
      |                                  |                            |
      |--------------------------------->|                            |
      |  after_tool_call(result)         |                            |
      |                                  | POST /api/v1/audit         |
      |                                  |---- (fire-and-forget) ---->|
      |                                  |                            | store event + alerts
      |<---------------------------------|                            | triage (background)
      | Return result to LLM            |                            |
      |                                  |                            |
```

### 6.2 OpenClaw Plugin Pseudocode

```typescript
// agentshield-plugin/index.ts

export function register(api: OpenClawPluginApi) {
  const config = loadAgentShieldConfig();
  const circuitBreaker = new CircuitBreaker(config.circuit_breaker);

  api.on("before_tool_call", async (event, ctx) => {
    // Skip if tool is in the skip list
    if (config.skip.includes(event.toolName)) {
      return null; // Allow without evaluation
    }

    // Skip if circuit breaker is open
    if (circuitBreaker.isOpen()) {
      return applyTimeoutPolicy(config.timeout_policy);
    }

    try {
      const response = await fetch(config.endpoint, {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          "X-AgentShield-Version": "1.0.0",
          "X-AgentShield-Auth": config.auth_token,
        },
        body: JSON.stringify(buildEvaluationRequest(event, ctx)),
        signal: AbortSignal.timeout(config.timeout_ms),
      });

      circuitBreaker.recordSuccess();

      if (!response.ok) {
        return applyTimeoutPolicy(config.timeout_policy);
      }

      const result = await response.json();

      if (result.action === "block") {
        return { block: true, blockReason: result.reason };
      }
      // "allow" and "log" both permit execution
      return null;

    } catch (err) {
      circuitBreaker.recordFailure();
      return applyTimeoutPolicy(config.timeout_policy);
    }
  });

  api.on("after_tool_call", async (event, ctx) => {
    // Fire-and-forget audit report
    fetch(`${config.endpoint.replace("/evaluate", "/audit")}`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(buildAuditReport(event, ctx)),
    }).catch(() => {}); // Best-effort
  });
}
```

### 6.3 AgentShield Handler Pseudocode

```python
# agentshield/realtime/server.py

async def handle_evaluate(request: web.Request) -> web.Response:
    """Handle POST /api/v1/evaluate."""
    body = await request.json()

    # Validate request
    event = parse_evaluation_request(body)

    # Synchronous detection (< 1ms)
    alerts = detection_engine.evaluate(event)

    # Determine action
    action = decide_action(alerts, config.block_threshold)

    # Build response
    response = build_evaluation_response(event.id, action, alerts)

    # Background: store event + alerts (non-blocking)
    asyncio.create_task(store_event_and_alerts(event, alerts))

    return web.json_response(response)
```

## 7. Authentication

### 7.1 Shared Secret Token

The simplest authentication mechanism suitable for localhost communication:

1. During AgentShield setup, a random token is generated and stored in AgentShield's config.
2. The same token is configured in the OpenClaw plugin's config.
3. Every request includes the token in a header.

**Header**: `X-AgentShield-Auth: <token>`

### 7.2 Token Generation

```bash
# Generated during `agentshield init` or first start
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Stored in:
- **AgentShield**: `~/.agentshield/config.yaml` under `realtime.auth_token`
- **OpenClaw**: OpenClaw config under `plugins.agentshield.auth_token`

### 7.3 Validation

AgentShield validates the token on every request to `/api/v1/evaluate` and `/api/v1/audit`:

```python
async def validate_auth(request: web.Request) -> bool:
    token = request.headers.get("X-AgentShield-Auth", "")
    return hmac.compare_digest(token, config.realtime.auth_token)
```

If validation fails: return HTTP 401 Unauthorized.

### 7.4 Token Rotation

Tokens can be rotated by:
1. Generating a new token
2. Updating both configs
3. Restarting both services

No rolling/dual-token mechanism in v1. This is acceptable for localhost-only communication.

### 7.5 No Authentication Mode

For development/testing, authentication can be disabled:

```yaml
# AgentShield config
realtime:
  auth_required: false
```

When `auth_required: false`, the `X-AgentShield-Auth` header is ignored.

## 8. Versioning Strategy

### 8.1 Contract Version

The contract version follows semantic versioning: `MAJOR.MINOR.PATCH`.

- **MAJOR**: Breaking changes to required fields, endpoint paths, or response structure.
- **MINOR**: Additive changes (new optional fields, new endpoints).
- **PATCH**: Bug fixes, documentation clarifications.

Current version: **1.0.0**

### 8.2 Version Negotiation

Every request from OpenClaw includes a version header:

```
X-AgentShield-Version: 1.0.0
```

AgentShield's response includes its supported version:

```
X-AgentShield-Version: 1.0.0
```

### 8.3 Compatibility Rules

- **Same MAJOR**: Fully compatible. AgentShield ignores unknown fields in requests. OpenClaw ignores unknown fields in responses.
- **Different MAJOR**: Incompatible. AgentShield returns HTTP 422 with error body:
  ```json
  {"error": "unsupported_version", "supported": "1.x", "received": "2.0.0"}
  ```

### 8.4 Forward Compatibility

Both sides follow these rules:
- **Ignore unknown fields** in JSON payloads (do not reject).
- **Treat missing optional fields** as their default values.
- **Never remove required fields** in a MINOR version bump.

This ensures a newer OpenClaw plugin can talk to an older AgentShield (and vice versa) within the same MAJOR version.

## 10. HTTP Error Codes

| Status | Meaning | When |
|---|---|---|
| 200 OK | Evaluation successful | Normal response with action |
| 400 Bad Request | Invalid request body | Missing required fields, invalid JSON |
| 401 Unauthorized | Authentication failed | Missing or invalid `X-AgentShield-Auth` |
| 413 Payload Too Large | Request body exceeds limit | Body > `max_request_size_bytes` |
| 422 Unprocessable Entity | Version incompatibility | MAJOR version mismatch |
| 500 Internal Server Error | Should never happen | Bug in AgentShield (returns allow) |
| 503 Service Unavailable | Server overloaded | Too many concurrent evaluations |

For `/api/v1/evaluate`: **any non-200 response is treated as evaluation failure** by the OpenClaw plugin, which applies the `timeout_policy`.

## 12. Security Considerations

### 12.1 Localhost-Only Binding

The real-time evaluation server MUST bind to `127.0.0.1` by default. Binding to `0.0.0.0` exposes the evaluation API to the network, which could allow:
- Remote event injection
- Denial of service
- Information leakage about detection rules

If remote access is needed (e.g., AgentShield on a different host), it should be tunnelled via SSH or a reverse proxy with TLS.

### 12.2 Request Size Limits

Maximum request body: 64KB (configurable). This prevents memory exhaustion from maliciously large payloads. Tool parameters are typically small (< 4KB for shell commands).

### 12.3 No Sensitive Data in Responses

AgentShield responses MUST NOT include:
- Full Sigma rule detection logic
- Internal database IDs or paths
- API keys or tokens
- User feedback data

Responses include only: action, rule IDs/names, alert levels, and a human-readable block reason.

### 12.4 Input Sanitisation

AgentShield MUST treat all fields in the evaluation request as untrusted input:
- Validate types and lengths before processing
- Never interpolate request fields into shell commands or SQL
- Use parameterised queries for database operations (already the case with aiosqlite)

### 12.5 Rate Limiting

Optional rate limiting on the evaluation endpoint to prevent abuse:

```yaml
realtime:
  rate_limit:
    enabled: false
    max_requests_per_second: 100
```

Default: disabled (localhost-only traffic is self-limiting).

## 15. Lifecycle Events

In addition to the synchronous `evaluate` path and the post-execution `audit` path, OpenClaw emits lifecycle events that provide session and agent context. These are sent as **fire-and-forget** POST requests to `/api/v1/lifecycle` and are used for:

- Building richer triage context (e.g., "this tool call happened within session X by agent Y")
- Detecting anomalous session patterns (e.g., unusually many tool calls per session)
- Correlating events across the agent lifecycle

### 15.1 Lifecycle Event Schema

All lifecycle events share a common envelope:

```jsonc
{
  "event_id": "string",           // UUID v4
  "timestamp": "string",          // ISO 8601
  "event_type": "string",         // One of the types below
  "source": "openclaw",
  "agent_id": "string | null",
  "session_id": "string | null",
  "data": {}                      // Event-type-specific payload
}
```

### 15.2 Event Types

#### `session_start`

Emitted when a new OpenClaw session is created.

```jsonc
{
  "event_type": "session_start",
  "data": {
    "channel": "string | null",       // "whatsapp", "telegram", "discord", "api", etc.
    "user_id": "string | null",       // Anonymised user identifier (no PII)
    "sandbox_mode": "string | null"   // "session", "agent", "shared", "off"
  }
}
```

#### `session_end`

Emitted when a session completes.

```jsonc
{
  "event_type": "session_end",
  "data": {
    "duration_ms": 0,                 // Total session duration
    "tool_calls_count": 0,            // Total tool calls in session
    "blocked_count": 0,               // Tool calls blocked by AgentShield
    "exit_reason": "string | null"    // "completed", "timeout", "error", "aborted"
  }
}
```

#### `agent_start`

Emitted before an LLM agent run begins (maps to OpenClaw's `before_agent_start`).

```jsonc
{
  "event_type": "agent_start",
  "data": {
    "model": "string | null",         // LLM model name
    "provider": "string | null",      // LLM provider
    "tool_count": 0,                  // Number of tools available to the agent
    "system_prompt_hash": "string | null"  // SHA-256 hash of system prompt (not the prompt itself)
  }
}
```

#### `agent_end`

Emitted after an agent run completes.

```jsonc
{
  "event_type": "agent_end",
  "data": {
    "duration_ms": 0,                 // Agent run duration
    "tool_calls_count": 0,            // Tool calls during this run
    "tokens_used": 0,                 // Total tokens consumed (if available)
    "exit_reason": "string | null"    // "completed", "max_tokens", "error", "aborted"
  }
}
```

#### `message_blocked`

Emitted when an outbound message is cancelled by the `message_sending` hook (if AgentShield integration is configured for message interception).

```jsonc
{
  "event_type": "message_blocked",
  "data": {
    "channel": "string",
    "reason": "string",
    "message_hash": "string"          // SHA-256 hash of message content (not the content itself)
  }
}
```

### 15.3 Endpoint

```
POST /api/v1/lifecycle
```

**Request**: Lifecycle event JSON (Section 15.1 envelope)
**Response**: `204 No Content`

Fire-and-forget: the OpenClaw plugin does not await the response. Failures are silently ignored.

### 15.4 AgentShield Processing

Lifecycle events are:
1. Stored in `EventStore` (same as all other events, with `source="openclaw"`)
2. Available for triage context (e.g., `ContextGatherer` can include session metadata)
3. Optionally matched against Sigma rules (e.g., detect sessions with > 100 tool calls)

Lifecycle events are **never** on the critical path and do not affect tool execution latency.
